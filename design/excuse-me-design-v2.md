# EXCUSE ME! 디자인 가이드

기준 문서 — EXCUSE ME! 제작 설명서 PDF  
슬로건 — Small Problem. Big Meeting. 사소한 거절을 위한 거대한 회의.

## 아트 디렉션

**큰 타이포와 작은 문구 캐릭터.** [Gumroad](https://gumroad.com/)에서 큰 헤드라인, 과감한 분할 색면, 진한 외곽선의 리듬을 참고한다. 첫 화면은 핑크 소개 영역과 라임 승인서 일러스트로 나눈다. 캐릭터는 얼굴이 있는 문구 소품으로 유지하며, 참고 이미지의 표정과 몸짓의 재미를 독자적인 실루엣으로 표현한다.

| 토큰 | HEX | 용도 |
|---|---|---|
| ink | #22201D | 본문, 2px 테두리, 4–9px 오프셋 그림자 |
| paper | #FFF9ED | 배경과 서류 |
| pink | #FFA8D0 | 소개 색면 |
| lime | #DDFA80 | 승인서 일러스트 배경, 선택 강조 |
| lilac | #C5B6FF | 회의 체험 배경 |

히어로 제목은 48–128px 사이에서 화면 폭에 따라 변하고 글자 간격은 -0.085em. 본문은 시스템 한글 서체 16px. 700px 이하에서는 히어로가 한 열로 쌓이고 캐릭터 카드는 가용 폭에 따라 줄을 바꾼다. 조작 요소는 모바일에서도 텍스트가 줄바꿈되며 키보드 포커스 링을 표시한다.

## Lusion 레퍼런스 적용 — 회의실로 들어가는 첫 장면

[Lusion의 3D 비주얼 스토리텔링과 인터랙션](https://lusion.co/)에서 공간을 탐색하는 감각을 가져온다. EXCUSE ME!에서는 **책상 위 결재 서류에 가까이 다가가면 위에서 내려다보는 핑계 회의실로 이어지는 장면**으로 풀어낸다. 밝은 종이색과 핑크·라임을 유지하고, 깊이감은 겹친 종이의 두께, 무광 문구 재질, 부드러운 접지 그림자로 만든다.

| 장면 | 연출 | 구현 기준 |
|---|---|---|
| 첫 화면 | 비스듬한 시점에서 안건철과 고무도장이 보인다. 제목과 ‘회의실 들어가기’를 바로 읽을 수 있다. | 장식 오브젝트만 포인터에 최대 4° 반응한다. 제목과 버튼은 고정한다. |
| 입장 | 스크롤을 내리면 책상에 가까워지고, 테이블이 정면 탑뷰에 가까워진다. 보드와 다섯 자리가 한 화면에 들어오는 순간 시점을 멈춘다. | 데스크톱은 약 60vh 구간에서 진행도를 연동한다. 버튼으로도 회의실에 바로 이동할 수 있다. |
| 잡담과 핑계 회의 | 발언자가 살짝 들리고 말풍선이 자리 옆에 뜬다. ‘강아지 돌잔치’처럼 황당한 후보가 나오면 작은 카드 한 장이 테이블에 올라온다. 검증이 받아치면 카드는 ‘회의용’ 표시와 함께 옆으로 밀린다. | 한 순간에 주된 움직임은 하나. 대사 3초, 퇴장 220ms, 다음 발언 전 여백 280ms를 기본으로 삼는다. |
| 승인서 | 테이블 위에 놓인 안건 카드가 화면 아래의 정돈된 승인서로 이어진다. | 후보는 이유 차이로 구분하고 문구는 각 후보의 한 줄 예시로 붙인다. 결재 버튼은 항상 읽고 조작할 수 있게 표시한다. |

### 반응형과 제작 범위

- **데스크톱** — 입장 구간에서는 서류·테이블·바닥을 서로 다른 깊이로 움직인다. 대화가 시작되면 시점을 고정하고 발언자와 소품만 반응시킨다.
- **모바일** — 스크롤 고정 없이 짧게 전환한다. 테이블 둘레의 다섯 자리와 중재의 상단 자리를 보존한다. 말풍선이 화면 가장자리나 캐릭터 이름과 겹치면 테이블 중앙의 발언 영역으로 옮기고 화자 이름을 함께 표시한다.
- **모션 감소** — 카메라 이동과 자동 잡담을 끈다. 탑뷰와 ‘다음 발언’, 텍스트 대화 기록으로 같은 내용을 읽을 수 있게 한다.
- **해커톤 우선순위** — CSS 원근과 그림자, 레이어 전환으로 입장 장면부터 만든다. WebGL은 시간이 남을 때 문구 오브젝트에 한해 검토한다. 안건 입력, 말풍선, 후보 선택과 결재는 HTML로 구현한다.

## 스크롤과 인터랙션

[GSAP](https://gsap.com/)의 장면 전환과 반응을 참고한다. 프리뷰는 CSS 키프레임, IntersectionObserver, requestAnimationFrame으로 구현한다.

| 장면 | 트리거 | 화면 반응 |
|---|---|---|
| 첫 화면 | 페이지 로드 | 제목 두 줄이 마스크 아래에서 120ms 간격으로 올라온다. 승인서는 기울어진 채 나타나고 마지막에 결재 도장이 찍힌다. |
| 승인서 | 포인터 이동 또는 스크롤 | 마우스 위치에 따라 최대 18px 이동하고 회전한다. 스크롤은 최대 54px만 반영한다. 터치는 포인터 추적 없이 스크롤에만 반응한다. |
| 멤버 소개 | 뷰포트 진입 | 캐릭터 카드가 90ms 간격으로 올라온다. 카드에 커서를 올리면 그림자가 길어지고 캐릭터가 살짝 기운다. |
| 회의 결과 | 안건 제출 | 발언 4개와 승인서가 110ms 간격으로 차례대로 나타난다. |
| 승인 | 답장 선택과 결재 | 선택한 카드에 라임 배경을 적용한다. 결재 완료 후 상태 문구가 나타나며 키보드 포커스를 받는다. |

등장 모션은 한 번 실행한다. 시각 효과는 요소의 위치나 크기 계산에 영향을 주지 않는다. 모션 감소 설정에서는 제목, 스크롤 이동, 카드 등장과 버튼 전환을 끄고 내용은 즉시 표시한다.

## 회의 화면

- 상단 로고와 안건, 중앙 발언과 승인서, 하단 입력창. 본문은 최대 720px. 모바일은 한 열로 쌓고 입력창이 승인 버튼을 가리지 않게 한다.
- “거절하고 싶은 약속이나 부탁을 알려 주세요.” 회식 시연 입력 예시 — “내일 팀 회식에 가기 어려운데 어떻게 말하면 좋을까요?”
- 안건 접수 → 전략 → 검증 → 인간관계 → 중재가 승인서 제시 → 사용자 결재 → 실행. 단계별 데이터 없이 대기하는 동안에는 “회의 중”을 표시한다.
- 역할명과 아바타를 함께 표시한다. 검증 표기는 “확인 도장”, “회의용 아이디어 · 발송 불가”. 캘린더 조회 없이 사용자 진술을 이용할 때는 “사용자 제공 정보”라고 표시한다.
- 1안과 2안을 같은 스타일로 제시하고 “다시 회의”로 새 조건을 입력하면 선택을 초기화한다. 결재 직전 실제 문구, 수신자, 일정 초대 포함 여부를 표시한다.
- 명시적 결재 후에만 발송을 시작한다. 메일과 초대 결과는 각각 도구 결과를 확인한 뒤 표시한다. 연동 없는 시연에서는 “시연 모드 · 실제 발송 없음”을 표시한다.

## 테이블 회의 장면

참고 이미지의 위에서 내려다보는 배치만 사용한다. 둥근 황금색 테이블을 중심으로 중재는 위, 전략과 검증은 좌우, 인간관계와 실행은 아래 양옆에 둔다. 안건 보드는 위쪽 중앙에 둔다. 기존 종이색·굵은 선과 문구 캐릭터를 유지한다.

- 회의실이 보이면 쿠키를 주제로 다섯 역할이 한 마디씩 주고받는다. 안건을 제출하면 잡담에서 핑계 회의로 전환하고, 결재하면 실행의 확인 발언을 표시한다.
- 말풍선은 발언자 쪽에 꼬리를 두고 한 번에 하나만 표시한다. 약 2.9초 표시한 뒤 230ms 동안 사라지고 다음 발언까지 280ms 쉰다. 현재 발언자의 아바타만 짧게 움직인다.
- 작은 화면에서도 마주 보는 자리 배치를 유지한다. 아바타와 테이블을 줄이고 말풍선 폭과 꼬리 위치를 화면에 맞춘다. 자동 대화 끄기, 다음 발언, 대화 기록을 제공한다. 모션 감소 설정에서는 자동 재생을 기본으로 끈다.
- 이 프리뷰의 잡담과 업무 대화는 스크립트로 구성한다. 사용자 안건은 보드에 표시한다.

## 실시간 회의 채팅

851px 이상의 화면에서는 회의실 오른쪽에 채팅을 둔다. 850px 이하에서는 회의실 아래에 붙인다. 한 발언 데이터로 자리의 말풍선과 채팅 기록을 동시에 갱신한다. 방금 발언은 노란 배경으로 강조한다. 최신 줄을 보던 경우에만 아래로 자동 스크롤한다.

캐릭터는 말풍선, 좌석, 채팅에서 같은 실루엣을 사용한다. 전략은 주황색 몸에 삐져나온 노란 카드, 검증은 파란 도장 손잡이와 남색 받침, 인간관계는 연분홍 봉투와 흰 덮개, 중재는 연두색 안건철과 상단 탭, 실행은 보라색 아치와 발송구로 표현한다.

## 캐릭터 말투와 결재 모션

| 역할 | 대화 스타일 | 시각 디테일 |
|---|---|---|
| 전략 | 능청스러운 영업맨. “특급 안건입니다! 축사는 서비스죠.” | 주황색 몸, 기울어진 카드, 짝눈썹 |
| 검증 | 감사 담당. 다혈질 반말로 사실 오류를 짧게 지적한다. “야, 강아지도 없잖아!” | 파란 도장, 진한 받침, 치켜뜬 눈썹 |
| 인간관계 | 걱정 많은 다정한 동료. “사정을 말하기 어려우면 안 밝혀도 괜찮아요.” | 분홍 봉투, 연한 덮개, 볼 색 |
| 중재 | 차분한 진행자에 현자 말투를 더한다. “껄껄껄. 어디 첫 후보를 들어볼까?” | 연두 안건철, 둥근 모자, 넓은 웃음 |
| 실행 | 과묵한 실무자. “결재 확인.” | 보라색 아치, 이중 테두리, 발송구 |

명시적 최종 결재 때만 뷰포트 중앙에 붉은 ‘결재’ 도장을 띄운다. 크게 내려와 한 번 눌린 뒤 1.25초 안에 사라진다. 화면 폭에 맞춰 크기를 조절하고 입력을 가로채지 않는다. 모션 감소 모드에서는 정지 도장을 잠깐 표시한다. 결재 완료 상태는 본문에 남긴다.

## 핑계 회의 연출

핵심 질문은 “무슨 이유로 빠질까?”다. 전략이 “강아지 돌잔치” 같은 황당한 후보를 던지면 검증이 받아치고 회의용으로 보류한다. 인간관계는 휴식이 필요하다고 밝히거나 사정을 공개하지 않는 방법을 꺼내고, 실행은 “답례품도 보류합니다”라고 받는다. 중재는 사용자가 실제 상황에 맞게 고를 수 있는 후보를 올린다. 문구는 각 후보 아래 한 줄 예시로 붙인다.

## 거절 승인서

웹은 종이색 카드, Word는 A4 세로 한 장. 제목은 “거절 승인서”. 하단에는 실제 상태를 반영한 결재 칸 네 개를 둔다.

| 위치 | 필드 |

2. **1:30–2:30** — Figma로 회의 화면과 승인서를 디자인하고 Word A4 양식에 같은 필드를 배치한다.
3. **2:30–3:00** — 시안 PNG와 웹 시안을 전달한다. A안은 캐릭터와 로고가 있는 페이지에 기본 Copilot 채팅을 삽입한다. B안은 부모 응답의 역할명 접두사와 승인서 블록을 아바타·말풍선·카드로 표시한다. 형식을 인식하지 못하면 원문을 표시한다.
4. **3:00–5:00** — 연동을 확인하고 원페이저에 승인서와 회의 시안을 우선 배치한다.
5. **5:00–6:00** — 회식 입력 → 다시 회의 → 안 선택 → 결재 → 발송 결과를 리허설한다.

## 구현 확인

- 360px 화면에서 가로 스크롤 없이 읽히고 키보드로 안 선택과 결재가 가능하다.
- 회의용 아이디어에는 선택 버튼이 없다. 최종 결재 전에는 발송이 시작되지 않는다.
- Word A4 한 장에 모든 필드와 결재 칸 네 개가 보인다.
